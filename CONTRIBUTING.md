# Contributing

## Before opening a pull request

- Keep changes focused and explain the user-visible impact.
- Run `./gradlew build --no-daemon` locally when possible.
- Do not commit secrets, generated credentials, or local IDE files.
- Include reproduction steps for bug fixes and testing notes for behavior changes.

## Pull requests

Use a short, descriptive title. Keep unrelated formatting or refactors out of the same pull request so changes remain easy to review.
